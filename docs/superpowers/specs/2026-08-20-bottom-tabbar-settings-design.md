# 原生底部导航与独立设置页设计

## 目标

把 Today 顶部的“历史”“我的”文字入口替换为微信原生底部导航，并将成长页中的合规说明和账户删除迁移到独立设置页。页面导航更符合微信小程序习惯，中文字体在 iOS 真机和 Windows 开发者工具中保持清晰一致。

## 导航结构

使用微信原生 `tabBar`，固定包含四项，顺序如下：

1. 今日：`pages/today/index`
2. 历史：`pages/history/index`
3. 我的：`pages/profile/index`
4. 设置：`pages/settings/index`

四个页面必须位于 `app.json` 的主包 `pages` 中。目标制定页 `pages/goal/index` 不是 tabBar 页面；目标确认完成后，所有进入 Today 的程序化跳转必须使用适用于 tabBar 页面的方式。tabBar 使用现有米白背景、青绿色选中态和深灰未选中态，不引入网络图标或第三方字体。

Today 必须是 `pages` 的第一项和冷启动首页。没有计划时，用户从 Today 通过 `navigate` 进入目标制定临时流程，因此目标页显示原生返回入口；用户可随时返回 Today，再使用底部导航切换其它页面。目标确认完成后通过 `switchTab` 回到 Today。

## 页面职责

### 今日

- 删除页面内容顶部的“历史”“我的”入口及对应空白占位。
- 保持计划、任务、提醒和复盘功能不变。
- 通过底部“今日”作为选中入口。

### 历史

- 删除“返回 Today”文字入口。
- 保持月份切换、日期选择、历史详情和重试行为不变。
- 为底部 tabBar 安全区保留足够滚动空间。

### 我的

- 只展示小橘、成长等级、累计成长值和最近三条成长事件。
- 完整删除“设置与说明”、AI 说明、隐私说明和删除账户区域。
- 删除账户后的成长清空显示逻辑随删除操作一并迁移，不继续留在成长页。

### 设置

- 新建独立页面，展示“AI 生成内容”“隐私与数据”“删除全部数据”。
- 迁移现有删除确认、加载态、成功提示和失败提示，服务端 `account-delete` 行为不变。
- 删除成功后设置页仅显示成功提示；用户切换到“我的”时，成长页通过 `onShow` 重新读取并显示空档案欢迎状态。

## 字体与视觉

全局中文字体使用系统字体栈：

```css
"PingFang SC", "Microsoft YaHei", sans-serif
```

不引入字体文件，避免增加包体和字体授权风险。标题字重限定为 600–700，正文为 400–500；移除成长页和历史页过重的 750/800 字重。原生 tabBar 负责底部文字渲染、选中态和安全区，页面不重复绘制自定义底栏。

## 数据与安全边界

- 不新增或修改云函数、数据库集合与索引。
- 设置页继续调用既有 `deleteAccount()` 客户端边界。
- 成长页继续通过受认证的 `growth-summary` 读取真实数据。
- 页面、日志和测试不得输出 OpenID、用户正文或密钥。

## 测试与验收

1. 先写失败测试，断言 `app.json` 包含四项原生 tabBar 和设置页路由。
2. 断言 Today 不再包含顶部“历史”“我的”入口，历史页不再包含“返回 Today”。
3. 断言成长页不含 AI、隐私和删除区域，设置页包含这些内容及 `onDeleteAccount`。
4. 断言所有跳转到 Today 的程序化路由均兼容 tabBar。
5. 断言字体栈包含苹方与微软雅黑，成长页和历史页不再使用 750/800 字重。
6. 运行全量 Vitest、TypeScript 类型检查和 `git diff --check`。
7. 微信开发者工具重新编译后，逐项点击“今日 / 历史 / 我的 / 设置”，确认选中态、页面状态和返回行为正常；未实际执行的真机项目只记录为“未验证”。

## 非目标

- 不自定义 tabBar 组件。
- 不新增提醒、账号或成长设置。
- 不改历史、成长、计划和删除的数据语义。
- 不提交、不推送、不创建或合并 PR。
