# 今日多目标看板设计

## 背景

当前“今日”页只按整份计划展示一个“现在开始”任务、后续任务和已完成任务。目标拆解页则通过左上角 Home 图标返回首页。用户无法在“今日”页直接比较多个目标的进度，也不能在同一天继续加入第二或第三个目标。

现有持久化模型已经是一名用户在一个上海自然日拥有一份确定性 ID 的正式计划，计划内的任务通过 `goalId` 关联目标。本设计继续保留“一天一份计划”，在该计划内支持最多三个目标，而不是创建三份相互独立的计划。

## 产品目标

1. “今日”成为当天唯一的目标与任务首页。
2. 一天最多展示和执行三个目标，三个目标合计最多十个任务。
3. 每个目标以可展开卡片显示独立进度和任务。
4. 用户可在展开区域直接开始、完成或缩小任务。
5. 每个目标最多有一个进行中任务；不同目标可同时各有一个进行中任务。
6. 未达到上限时，用户可从“今日”进入现有目标拆解流程并把新目标安全追加到当天计划。

## 非目标

- 不创建同一天的多份计划文档。
- 不把完整目标澄清表单直接嵌入“今日”页。
- 不增加目标拖拽排序、目标删除、跨天排期或历史编辑。
- 不为每个目标分别创建提醒或复盘；提醒和复盘仍属于整份今日计划。
- 不改变“历史 / 我的”主导航结构；设置仍位于“我的”内。
- 不迁移或重写已有计划。

## 核心规则

### 每日容量

- 每个上海自然日最多三个不同的 `goalId`。
- 一份今日计划最多十个任务。
- 每个加入今日的目标至少包含一个任务；单次目标拆解仍最多生成五个任务。
- 新目标生成计划时，服务端依据当天现有任务计算剩余名额，生成数量不得超过 `min(5, 10 - 当天任务数)`。
- 目标数已达三个或任务数已达十个时，“拆解新目标”入口不可用，并显示原因。
- 所有容量上限必须由服务端在事务内再次校验，前端提示不能作为唯一保护。

### 任务执行

- 每个任务只属于一个目标。
- 同一目标最多有一个 `in_progress` 任务。
- 不同目标之间互不阻塞，因此一天最多可以同时有三个 `in_progress` 任务。
- 开始任务时，服务端必须检查同一 `goalId` 下是否已有另一个进行中任务。
- 缩小任务后仍保留原任务的 `goalId`；“移到队尾”只影响同一目标内的顺序。

### 追加而非覆盖

- 当天还没有计划时，第一次确认创建正式计划。
- 当天已有计划时，确认第二或第三个目标必须把新任务原子追加到原计划。
- 追加不得覆盖、重置或重新编号已有任务的状态、难度反馈、开始时间和完成时间。
- 相同请求重试只返回同一结果，不重复追加任务。
- 同一目标重复加入今日时不新增第二组任务。
- 并发追加后若目标数或任务数超过上限，其中一个请求必须得到稳定的上限错误，不能产生部分写入。

## 今日页信息架构

### 页面顶部

页面顶部显示：

- “今日计划”与原有温和文案。
- 今日总体进度，例如“已完成 4/8 项”。
- 今日目标容量，例如“今日目标 2/3”。

总体进度按整份计划的任务数计算，不替代各目标的独立进度。

### 目标折叠卡片

目标卡片按首次加入今日的顺序纵向排列。默认只展开一个目标：优先展开含进行中任务的第一张卡片；没有进行中任务时展开第一个未完成目标。用户点击其他卡片时切换展开项，再次点击当前卡片可收起。

收起态展示：

- 猫爪或小猫视觉标记。
- 目标名称。
- 状态文字：“未开始 / 进行中 / 已完成”。
- 进度条和“已完成 X/Y 项”。

状态和进度不能只通过颜色表达。当前展开卡片使用现有深青色、暖金色和圆角层级强化，不新增网络素材、emoji 或第三方图标库。

展开态按该目标内部顺序展示：

1. 进行中的任务。
2. 待开始的任务。
3. 已完成的任务。

任务继续复用现有任务卡交互：

- 待开始任务可“开始”或“缩小一步”。
- 进行中任务可“完成”或“缩小一步”。
- 完成任务时继续记录“轻松 / 刚好 / 困难”反馈。
- 已完成任务保持可见但只读。
- 同一目标已有进行中任务时，该组其他待开始任务不提供可执行的“开始”操作，并说明先完成当前一步；其他目标的任务仍可开始。

### 新目标入口

- 当目标数少于三个且任务数少于十个时，在目标列表末尾显示“＋拆解新目标”。
- 点击后进入现有 `pages/goal/index` 专注拆解流程。
- 正常用户路径从“今日”以 `navigateTo` 进入目标拆解页，微信原生导航因此提供返回上一页能力；产品不再提供或依赖额外的 Home 入口。开发者工具若把目标页直接设为启动页，仍可能显示微信管理的系统 Home 控件，本功能不改成自定义导航栏去隐藏它。
- 确认新目标和计划后自动返回“今日”，刷新并展开刚加入的目标卡片。
- 达到三个目标时提示：“今天已经有 3 个目标啦，先陪它们走完吧。”
- 达到十个任务时提示：“今天已经安排了 10 个小步，先完成一些再继续吧。”完成任务不会释放计划容量；当天任务总数仍保持最多十个。

## 页面状态

- **加载中**：保留“正在翻开今天这一页…”反馈。
- **完全空白**：显示轻量引导和主按钮“拆解第一个目标”。
- **部分进行**：显示总体进度、目标卡片和新增入口。
- **全部完成**：目标卡片继续显示完成进度，并提供整份计划的复盘入口。
- **加载失败**：显示稳定错误和“再试一次”，不隐藏已有本地页面结构。
- **任务操作失败**：错误保留在对应目标卡片内，用户可重试刚才的操作。
- **追加失败**：保留已确认目标和计划预览，允许以同一请求安全重试；不得清空原有今日进度。

## 数据与服务边界

### 今日读取

`plan-get-today` 在可信微信身份下读取当天唯一计划，并按任务中的不同 `goalId` 查询当前目标名称。响应向客户端提供适合渲染的目标分组：

```text
groups[]
  goalId
  goalTitle
  tasks[]
```

目标查询必须继续校验 `_openid`。目标不存在时使用稳定回退名称“今日目标”，任务内容仍可执行。目标名称不重复写入每个任务，也不要求迁移旧计划。

### 计划生成

进入新目标拆解流程后，计划生成服务读取当天现有计划，计算剩余目标数和任务名额。若仍可追加，只为新目标生成不超过剩余名额的任务；若没有容量，返回稳定的容量错误，不调用 AI。

### 计划确认

计划确认仓储由“只在不存在时保存”扩展为事务内“创建或追加”：

1. 从 `WX_OPENID` 获取可信身份和上海日期。
2. 验证新目标属于当前用户且仍处于 active 状态。
3. 读取当天确定性计划文档。
4. 不存在时创建；存在时保留原字段并追加新目标任务。
5. 校验合并后不同目标不超过三个、总任务不超过十个。
6. 为新增任务生成不会与旧任务冲突的确定性 ID，并接续该目标的任务顺序。
7. 保存已处理请求 ID，以支持第二、第三次确认和网络重试幂等。
8. 返回合并后的完整计划。

旧计划保留原 `requestId`。新实现允许兼容读取旧字段，并使用附加的已处理请求 ID 集合记录后续追加，不需要批量迁移。

`availableMinutes` 表示整份今日计划的总预算，追加时累加新目标确认的可用分钟数。计划总摘要由服务端生成稳定的多目标汇总，不直接拼接多段 AI 文案。

### 任务更新

`plan-update-task` 继续在事务中更新一份计划。开始操作新增同目标互斥检查；跨目标开始保持允许。任务响应返回完整合并计划，客户端据此重新计算各卡片进度。

## 兼容性

- 旧的一目标计划自然显示为一张目标卡片。
- 现有任务状态和难度反馈保持原格式。
- 历史页继续按 `goalId` 分组，需验证一天多目标时能完整展示所有组。
- 复盘仍统计整份计划的全部任务，只在整份计划满足现有复盘条件时开放。
- 今日提醒仍针对整份计划，不在本次设计中扩展为三个目标分别提醒。
- 客户端、云函数和响应验证器中原有“最多五个任务”仅保留为单次生成限制；今日合并计划的读取与更新上限改为十个。

## 无障碍与安全区

- 每个目标卡片标题和折叠控制的触控区域至少约 44 像素。
- 展开状态、任务状态和进度同时使用形状、文字和颜色表达。
- 目标名称和任务正文允许在大字模式下自然换行，不固定高度截断。
- 页面底部为自定义导航和系统安全区保留空间；新增按钮、最后一张展开卡片和复盘入口不能被遮挡。
- 日志和测试输出不得包含 OpenID、目标正文、任务正文、API Key 或完整上游响应。

## TDD 与验证

所有行为先增加会按预期失败的测试，再做最小实现。

自动测试至少覆盖：

1. 当天首次确认创建计划，第二和第三个不同目标原子追加。
2. 同一请求重试不重复追加，同一目标不会生成重复分组。
3. 第四个目标和第十一个任务被服务端稳定拒绝。
4. 追加不改变已有任务状态、反馈、时间戳和 ID。
5. 同一目标不能同时开始两个任务，不同目标可以同时开始任务。
6. 缩小和移到队尾不会改变目标归属，也不会影响其他目标的顺序。
7. Today 响应只返回当前微信身份的目标名称，并在目标缺失时回退。
8. 客户端把一至三个目标正确分组，并分别计算完成数量、总数和进行中任务。
9. 折叠卡片、展开任务操作、新增入口和目标/任务上限文案存在且路由正确。
10. 空白、加载、失败、全部完成和复盘状态继续可用。
11. 历史页能只读展示一天内最多三个目标的任务。
12. 375px 小屏、底部导航安全区和大字模式下没有内容遮挡或关键文字截断。

实现完成后运行相关聚焦测试、全量测试、TypeScript 类型检查、受影响 CloudBase 云函数构建和 `git diff --check`。微信开发者工具中人工验证首次目标、追加第二和第三目标、并行开始三个目标的任务、任务缩小、完成反馈、容量上限、草稿离开确认、历史展示和复盘闭环。

## 验收标准

1. 用户不依赖 Home 图标即可从“今日”查看当天全部目标和进度，并能沿正常页面栈返回“今日”。
2. 一天最多三个目标、十个任务，前后端对上限的判断一致。
3. 每张目标卡片都能展开，并可直接开始、完成或缩小该目标的任务。
4. 同目标最多一个进行中任务，三个不同目标可同时各有一个进行中任务。
5. 新目标确认后追加到今天，不覆盖已有目标、任务或进度。
6. 旧的一目标计划、提醒、历史、复盘和底部导航继续工作。
7. 自动检查通过，真机或微信开发者工具人工验收结果有明确记录。
