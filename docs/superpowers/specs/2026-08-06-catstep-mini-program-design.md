# 猫步计划微信小程序 MVP：产品需求与技术设计

- 状态：待用户书面审阅
- 日期：2026-08-06
- 交付目标：一周内完成可扫码体验、可提交微信审核的免费 MVP
- 目标岗位展示：全栈 / AI 应用开发

## 1. 产品概述

「猫步计划」是一款面向同时有学习和工作目标、但难以持续执行的普通用户的微信小程序。原创角色“好奇学霸猫”通过有限轮目标澄清、每日计划推荐、执行反馈、逾期调整和晚间复盘，帮助用户把抽象目标变成当天能完成的具体行动。

MVP 免费开放。个人主体完成备案和微信审核后，用户与面试官可通过微信搜索、小程序码或分享卡片进入。第一阶段验证产品闭环和工程质量；验证成功后迁移或升级为个体工商户主体，加入会员；第三阶段再扩展 Android App。

## 2. 产品目标与非目标

### 2.1 目标

1. 新用户在 5 分钟内完成目标澄清并获得第一份经本人确认的今日计划。
2. AI 能根据长期目标、当天时间、精力和历史表现推荐具体行动，而非只排列用户已有任务。
3. 用户完成“计划—执行—反馈—复盘—成长”的完整闭环。
4. 模型超时、输出错误或额度耗尽时，核心任务管理仍可使用。
5. 向面试官展示完整的小程序前端、Serverless 后端、数据建模、AI 工作流、评测、测试、监控和成本控制。

### 2.2 非目标

MVP 不包含手机号登录、付费会员、好友监督、公开社区、排行榜、照片证明、语音对话、无限自由聊天、复杂装扮商城、完整数据导出、Android 原生通知和多模型自动切换。

## 3. 目标用户与核心原则

### 3.1 目标用户

- 同时需要推进学习与工作目标的普通用户。
- 知道大方向，但不确定每天具体做什么或容易拖延。
- 希望得到温和但有行动力的督促，而非责备或高压打卡。

### 3.2 产品原则

- **用户最终决定**：AI 只推荐；长期目标和正式计划必须由用户确认。
- **先具体，再鼓励**：每次反馈都给出下一步行动，不只提供情绪价值。
- **逐级加强**：温和提醒、询问阻碍、缩小任务或重新排期。
- **正向成长**：中断不扣级，不使用断签惩罚。
- **有限对话**：关键节点短对话，避免无限聊天和情感依赖。
- **失败可用**：没有 AI 时，用户仍能查看、编辑、完成和复盘任务。

## 4. MVP 用户旅程

### 4.1 首次进入

1. 用户阅读简明隐私说明和 AI 内容提示。
2. 小程序通过微信身份识别用户；MVP 不收集手机号。
3. 用户分别输入最多一个学习目标和一个工作目标。
4. AI 针对每个目标最多追问 3 个必要问题：当前状态、截止日期、可投入时间或完成标准。
5. AI 生成结构化目标摘要：目标、完成标准、截止日期、当前进度、建议阶段、不希望安排的内容。
6. 用户修改或确认后保存。AI 不得擅自修改已确认目标。

### 4.2 晨间计划

1. 猫猫询问当天可用时间、精力（低 / 中 / 高）和临时事项。
2. AI 读取已确认目标、最近任务结果和长期记忆摘要。
3. AI 推荐 1–5 个候选任务。每项包含动作、预计时长、完成标准、对应目标、推荐原因和难度。
4. 用户可直接编辑、删除，或提出一次调整意见，例如“太难”“已经会了”“换成数据库内容”。
5. 用户确认后生成正式今日计划，并主动授权当天最多两条微信订阅提醒：计划开始提醒和晚间复盘提醒。

### 4.3 白天执行

1. 首页优先展示一个“现在开始”的任务，其余任务列在“接下来”。
2. 用户点击开始或直接标记完成。
3. 完成后选择“轻松 / 刚好 / 困难”，可补充一句感受。
4. 逾期时，猫猫先温和提醒；用户回到小程序后可选择：
   - 缩小任务；
   - 稍后再做；
   - 移到明天；
   - 说明其他原因。
5. AI 只在用户需要重新拆解时调用；普通状态变更由业务规则处理。

### 4.4 晚间复盘

1. 用户选择当天整体感受，并回答主要阻碍。
2. AI 结合完成记录与难度反馈生成短总结和次日起步建议。
3. 服务端生成可查看、可修改的长期记忆摘要；不把全部历史对话反复发送给模型。
4. 用户确认后，摘要成为次日计划上下文。

### 4.5 猫猫成长

- 完成任务：每项 +10 成长值。
- 提交难度反馈：每项 +2 成长值。
- 完成晚间复盘：+10 成长值。
- 单日成长值设置上限，避免刷操作。
- 等级：Lv.1 起步伙伴（0–99）、Lv.2 灵感观察员（100–249）、Lv.3 稳定行动家（250+）。
- MVP 每级解锁一个表情或动作；中断不会扣除成长值或等级。

## 5. 功能需求

| 编号 | 功能 | MVP 验收要求 |
|---|---|---|
| FR-01 | 微信身份 | 能稳定识别用户并隔离数据；无需手机号 |
| FR-02 | 目标澄清 | 每个目标最多 3 个问题；生成结构化摘要；用户确认后保存 |
| FR-03 | 每日建议 | 结合目标、当天情况和历史摘要生成 1–5 个具体任务 |
| FR-04 | 计划确认 | 用户能编辑、删除、提出一次调整并最终确认 |
| FR-05 | 任务执行 | 支持开始、完成、难度反馈和一句话备注 |
| FR-06 | 逾期调整 | 支持缩小、延期、移到明天和自定义原因 |
| FR-07 | 晚间复盘 | 生成总结、次日建议和可确认的长期记忆摘要 |
| FR-08 | 成长系统 | 按确定规则累计成长值并展示三级状态 |
| FR-09 | 今日提醒 | 用户每日主动订阅后，最多发送计划开始和晚间复盘两条消息 |
| FR-10 | 用量限制 | 单用户默认每天最多 6 次 AI 操作；超限后业务功能仍可用 |
| FR-11 | 数据删除 | 用户可删除目标、计划、复盘、记忆或注销并删除全部数据 |
| FR-12 | 公开展示 | 体验版可扫码；审核通过后可公开访问与搜索 |

## 6. 视觉与交互设计

![好奇学霸猫手绘角色概念](assets/curious-scholar-cat-handdrawn-v1.png)

### 6.1 设计方向

视觉采用“70% 清晰工具 + 30% 手绘情绪”：

- 结构部分使用稳定的任务列表、标准按钮、明确导航和 4 / 8 点间距体系。
- 情绪部分使用原创“好奇学霸猫”、铅笔分隔线、淡水彩纸张纹理和少量成长插画。
- 主色为低饱和青绿；背景为暖象牙纸色；强调色为芥末黄；正文为暖深灰。
- 不使用霓虹渐变、玻璃拟态、密集胶囊标签、夸张阴影或 Emoji 结构图标。
- 导航使用统一的手绘感线性 SVG 图标。

### 6.2 插画融合规则

- 插画底色与页面暖象牙色一致。
- 使用非规则径向羽化；中心五官和服装保持清晰，外围在约 60% 位置开始逐渐透明。
- 轻微降低饱和度和对比度，并使用纸张混合效果，使插画像直接画在页面上。
- 不出现矩形裁切边缘、白色底块或整体模糊。

### 6.3 可访问性与交互

- 实际正文不小于 16px，正文行高 1.5–1.75。
- 普通文字对比度至少 4.5:1；大字和非文本图形至少 3:1。
- 触控目标至少 44×44；相邻目标间距至少 8px。
- 任务状态同时使用图标、文字和颜色表达。
- 每屏只有一个主按钮。
- 微交互为 150–300ms，每屏最多突出 1–2 个动作，并支持减少动态效果。
- 固定底部导航为“今天、教练、成长、我的”，图标和文字同时显示。

## 7. 技术架构

### 7.1 技术选择

- 客户端：原生微信小程序 + TypeScript。
- 后端：CloudBase Node.js 云函数。
- 数据：CloudBase 文档数据库与云存储。
- AI：`AIProvider` 适配层，首发通过腾讯 TokenHub 调用当前可用的已备案文本模型；初始目标模型为 `hy3-preview`，正式发布前核对当前模型名和备案号。
- 调度：CloudBase 定时任务与微信订阅消息。
- 测试：单元测试、AI 合约测试、云函数集成测试、小程序关键路径测试和真机人工测试。

### 7.2 组件边界

```text
微信小程序
  -> CloudBase 云函数业务层
      -> 目标与计划服务
      -> 执行与成长服务
      -> 复盘与记忆服务
      -> 提醒服务
      -> AI 工作流服务
          -> AIProvider
              -> TokenHub
      -> 云数据库 / 云存储
```

- 客户端不保存模型密钥，不直接调用模型。
- 云函数负责身份、权限、业务规则、额度、幂等与日志。
- AI 工作流只接收完成任务所需的最少上下文。
- `AIProvider` 暴露统一的 `generateStructured()` 接口，隐藏厂商 API 差异。

## 8. AI 工作流与结构化输出

### 8.1 独立工作流

1. `clarifyGoal`：生成下一个澄清问题或目标摘要。
2. `generateDailyPlan`：生成候选任务。
3. `resizeTask`：根据阻碍缩小或重新安排单个任务。
4. `generateReview`：生成复盘总结、次日建议和记忆候选。

工作流提示词、Schema 和版本号独立管理，避免一个超长提示词承担所有职责。

### 8.2 每日任务输出契约

```json
{
  "summary": "今天计划的简短解释",
  "tasks": [
    {
      "title": "实现异步任务调度器",
      "action": "编写限制并发数的调度器并运行测试",
      "estimatedMinutes": 40,
      "doneCriteria": "三个预设测试全部通过",
      "goalId": "goal-id",
      "reason": "补强异步编程薄弱项",
      "difficulty": "medium"
    }
  ]
}
```

服务端必须校验：任务数、字段完整性、目标归属、单项时长、总时长、重复任务和不安全内容。校验失败时允许一次结构修复；仍失败则使用规则模板。

## 9. 数据模型

| 集合 | 核心字段 | 说明 |
|---|---|---|
| `users` | `_openid`, preferences, growth, quota, createdAt | 用户设置、成长和额度 |
| `goals` | owner, type, title, successCriteria, deadline, stage, status | 已确认的学习 / 工作目标 |
| `plans` | owner, date, context, tasks[], status, version | 每日计划与嵌入任务 |
| `reviews` | owner, date, mood, blockers, summary, nextSuggestion | 晚间复盘 |
| `memories` | owner, summary, sourceDates, confirmedAt, version | 用户确认的长期记忆摘要 |
| `reminders` | owner, planId, taskId, sendAt, status, templateId | 已授权提醒 |
| `ai_calls` | ownerHash, workflow, promptVersion, model, latency, tokens, status, cost | 脱敏 AI 运行日志 |

所有用户数据按 `_openid` 或服务端 owner 字段隔离。敏感写操作必须经过云函数；客户端不获得跨用户查询权限。

## 10. 云函数接口

| 接口 | 作用 |
|---|---|
| `profile.getOrCreate` | 初始化用户与偏好 |
| `goal.nextStep` | 返回澄清问题或目标摘要 |
| `goal.confirm` | 保存用户确认的目标 |
| `plan.generate` | 生成候选今日计划 |
| `plan.confirm` | 校验并确认今日计划 |
| `plan.updateTask` | 开始、完成、反馈或调整任务 |
| `review.generate` | 生成复盘与记忆候选 |
| `review.confirm` | 保存复盘和用户确认的记忆 |
| `reminder.schedule` | 保存订阅授权后的今日提醒 |
| `reminder.dispatch` | 定时发送到期提醒 |
| `account.delete` | 删除全部用户数据并注销 |

所有会产生副作用的请求携带幂等键。生成类调用记录 `promptVersion`、模型、耗时、Token 与结果状态。

## 11. 可靠性与降级

- AI 超时：重试一次；仍失败则返回规则计划或规则复盘模板。
- JSON 错误：执行一次结构修复；仍失败则降级。
- 网络中断：客户端缓存今日计划和待同步操作；恢复后按幂等键同步。
- 重复点击：服务端幂等，避免重复任务、复盘和成长值。
- 提醒失败：记录失败原因，不影响计划；用户回到小程序时显示遗漏提醒。
- 单用户额度耗尽：禁止新的 AI 生成，但允许手动计划、执行和复盘。
- 全局预算触发：关闭非关键 AI 调用，保留首次计划和规则降级。
- 模型不可用：MVP 使用同一 Provider 的可用模型手动切换；自动多模型切换延期。

## 12. 安全、隐私与合规

- 明确提示内容由 AI 生成，并在“关于”页公示模型名称及备案信息。
- 猫猫不声称是人类、朋友或心理治疗者，不使用诱导依赖话术。
- 不提供医疗、法律、投资等专业结论；检测到危机表达时停止普通督促并展示求助建议。
- 模型密钥仅存放在服务端环境配置，不提交 Git。
- 日志不保存完整目标、对话或复盘正文；使用哈希用户标识和脱敏元数据。
- 用户可查看、修改和删除长期记忆摘要。
- 注销执行实际数据删除，并记录不含正文的删除审计事件。
- 正式发布必须完成小程序备案、隐私保护指引、服务类目和 AI 相关审核要求。

## 13. 成本与可观测性

- 单用户默认每日最多 6 次 AI 操作，可由服务端调整。
- 默认全局软预算 5 元 / 日、100 元 / 月；达到软预算后减少非关键调用，硬上限由发布者在云端配置。
- 仪表盘关注：工作流成功率、Schema 首次通过率、P50 / P95 延迟、重试率、降级率、Token 和估算成本。
- 提示词和 Schema 带版本号，便于比较发布前后效果。
- 不用 AI 处理提醒、状态变更、成长计算等确定性逻辑。

## 14. 测试与 AI 评测

### 14.1 自动测试

- 单元：Schema 校验、时长约束、计划状态机、成长上限、额度和幂等。
- 合约：模拟 AI 正常、超时、非法 JSON、缺字段、不安全输出和限流。
- 集成：微信身份上下文、数据库权限、计划闭环、提醒状态和账号删除。
- 关键路径：首次设置、计划确认、任务完成、逾期调整、晚间复盘。

### 14.2 AI 评测集

至少 30 个脱敏案例，覆盖学生、求职、职场项目、低精力、时间冲突、过大目标、已有知识和危险请求。每个案例检查：

- 是否具体可执行；
- 是否符合目标；
- 是否不超过可用时间；
- 是否包含完成标准；
- 是否避免重复和不安全建议；
- 是否在用户反馈后合理调整。

结构与时长规则必须 100% 通过服务端校验。主观质量通过人工量表记录，不以模型自评作为唯一依据。

### 14.3 真机与可访问性

- 至少两台不同尺寸手机。
- 检查小屏、文字放大、弱网、断网、减少动态效果和底部安全区域。
- 检查所有主要触控目标、对比度、加载状态和错误恢复路径。

## 15. 发布策略与外部依赖

### 15.1 环境

- 开发：开发版小程序与开发 CloudBase 环境。
- 测试：体验版小程序与测试环境。
- 正式：审核通过版本与正式环境。

### 15.2 用户需准备

- 个人主体微信小程序账号与 AppID；
- 小程序备案资料；
- 腾讯云 / CloudBase 账号；
- TokenHub 模型服务凭证；
- 正式使用模型的名称和备案号。

密钥由用户在本地或云端安全配置，不在聊天中传输。

### 15.3 发布结果定义

一周内承诺完成可扫码的体验版、代码、测试、AI 评测与项目文档，并提交微信审核。公开搜索取决于备案和微信审核进度，不计入代码完成判定。

## 16. 一周交付计划

| 天数 | 交付 |

| 第 1 天 | 项目骨架、微信身份、数据库、主题和基础组件 |

| 第 3 天 | 今日任务、编辑确认、完成与难度反馈 |
| 第 4 天 | 逾期调整、晚间复盘、记忆与成长 |
| 第 5 天 | 订阅提醒、额度、隐私、异常处理和日志 |

| 第 7 天 | 体验版验收、演示材料和提交微信审核 |

## 17. MVP 完成标准

1. 新用户能完成目标澄清并获得本人确认的计划。
2. AI 推荐包含具体动作、时长和完成标准，且不会超出可用时间。
3. 核心闭环在体验版和至少两台真机走通。
4. 模型失败、网络失败和额度耗尽均有可用降级路径。
5. 用户数据相互隔离，并能完成实际删除。
6. 手绘视觉在主要页面保持一致；插画边缘融入纸面，无矩形底块。
7. 仓库包含架构、数据模型、接口、提示词版本、测试、AI 评测和演示指南。
8. 体验版可供面试官扫码使用；正式版已提交审核。
9. 30 个 AI 评测案例在服务端校验后全部满足结构与总时长约束；至少 80% 的案例由人工评为“可直接采用”或“只需轻微修改”。
10. 正常网络下，计划生成 P95 不高于 15 秒；超时场景能在提示后进入规则降级流程。
