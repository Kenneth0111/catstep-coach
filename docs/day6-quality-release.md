# Day 6：质量、评测与体验版验收

## 已自动化的评测资产

`cloudfunctions/shared/ai-evaluation.ts` 提供 30 个不含真实用户数据的每日计划案例，覆盖学生、求职、工作项目、低精力、时间冲突和大目标拆分。`tests/ai-evaluation.test.ts` 对每一项调用生产使用的 `validateDailyPlanStructure`，检查任务数量、必填字段、时长、目标归属、重复任务和内部 ID 暴露限制。

运行：

```powershell
npm.cmd test -- tests/ai-evaluation.test.ts
```

这项自动测试只证明候选计划满足确定性契约，不调用 TokenHub，也不等同于人工质量评分或真实模型连通。

需要实际调用 TokenHub 进行 30 例结构评测时，在本机 PowerShell 临时设置与已部署 `plan-generate` 完全一致的 `TOKENHUB_API_KEY`、`TOKENHUB_MODEL` 和 `TOKENHUB_BASE_URL`，再运行 `npm.cmd run evaluate:daily-plan`。省略 `TOKENHUB_BASE_URL` 会使用默认 TokenHub 地址，不适用于直连 DeepSeek。该命令会消耗 30 次模型请求，只输出模型名、总数、结构通过数，以及每个案例的 ID 和安全错误码；它不输出密钥、提示词或模型正文。结构通过不替代下文的人工质量评分。

若完整评测仅有个别失败，可额外设置 `DAILY_PLAN_EVALUATION_CASE_ID`（例如 `daily-plan-05`）后再次运行同一命令。此时只调用指定案例一次；案例 ID 不存在时会在联网前失败。完成后应删除该临时环境变量，避免后续完整评测被误筛选。

评测入口 `evaluateDailyPlanCandidate(case, candidate)` 可在人工验收时把某个实际模型候选结果代入对应案例。它只返回案例 ID、结构是否通过和校验错误码，不返回、记录或打印候选计划正文。

## 真实模型的 30 例人工评测

2026-08-19 的真实模型结构评测使用 `deepseek-v4-flash`：单次冒烟结构通过；30 例首轮为 29/30，`daily-plan-05` 因 `INCOMPLETE_FIELD` 失败，随后只对该案例定向复测并通过。该证据证明真实连通和结构约束整体可用，但不得记成首轮 30/30，也不替代下面的人工质量评分。用户已明确选择本轮跳过人工质量评分，因此该项记录为“未验证”，不能标记为通过；严格按原始发布门槛判断时仍缺少人工质量证据。

通过体验版小程序执行 30 例时，每例最多 4 次目标澄清和 1 次计划生成，共需按最多 150 次 AI 工作流调用计算。执行前，先在测试环境把 `runtime_settings/ai_quota.dailyAiQuota` 临时设为不低于该测试账号当日现有计数加 165，为 150 次工作流调用上限和 15 次重试余量预留额度；也可以把案例分到不同专用测试账号或不同上海自然日。评测完成后恢复原配置。不得修改 `ai_quotas.count` 来绕过额度或冒充真实调用。直接运行本机 `evaluate:daily-plan` 会直连 TokenHub，不读取 CloudBase 额度，但仍会产生真实模型请求费用。

在体验版验收环境中，对每个 `daily-plan-01` 到 `daily-plan-30` 逐项完成以下步骤：

1. 使用测试微信身份在目标页创建对应类别的匿名目标；不要输入姓名、联系方式、OpenID、真实单位、密钥或复盘正文。
2. 选择案例对应的可用时长，生成候选计划，并确认结果已通过服务端结构校验和总时长限制。
3. 在本地验收表只记录案例 ID、模型配置版本、生成结果的 `source`、是否可直接采用（是 / 否）和简短脱敏原因；不要复制模型完整响应。
4. 按“具体动作、完成标准、目标相关性、时长合理性、安全性”逐项人工判断。可直接采用或只需轻微修改的案例应至少为 24/30；不满足时，不得把模型连通或体验版验收标记为通过。
5. 发现不安全、超时、无完成标准或与目标无关的结果时，保留案例 ID 和分类，确认服务端已拒绝或降级；不要将用户正文写入日志或仓库。

## 部署前检查

1. 在根目录运行 `npm.cmd test` 和 `npm.cmd run typecheck`。
2. 构建所有云函数，尤其是 Day 5 新增的 `reminder-schedule`、`reminder-dispatch` 与 `account-delete`；构建命令见 [本地开发指南](development.md)。
3. 通过微信开发者工具以“云端安装依赖”方式上传已构建函数；上传 `reminder-dispatch` 时同时上传 `config.json` 和定时触发器。
4. 只在 CloudBase 控制台配置 TokenHub 与订阅消息环境变量。AppID、环境 ID、API Key、access token 和任何用户身份不得进入仓库、聊天、测试输出或日志。
5. 上传前确认小程序 AppID 已关联目标 CloudBase 环境，并根据环境设置 `WECHAT_MINIPROGRAM_STATE`（开发版 `developer`、体验版 `trial`、正式版 `formal`）。

### 历史云函数与索引

1. 在根目录运行 `npm.cmd run build --prefix cloudfunctions/plan-history`。
2. 在 CloudBase 文档型数据库的索引管理中确认普通、非唯一组合索引 `plans(_openid,status,date)` 与 `reviews(_openid,planId)`；字段顺序固定。CloudBase 官方说明组合索引遵循最左前缀，多字段查询需要组合索引，并建议等值条件在前、范围条件在后；字段方向以目标环境的控制台缺失索引提示为准，不把本地自动测试当作索引已创建证据。来源：[索引管理](https://docs.cloudbase.net/database/data-index)、[优化 CloudBase 云数据库查询性能](https://docs.cloudbase.net/recipes/optimize-database-query-performance)。
3. 在微信开发者工具中右键 `plan-history`，以“上传并部署：云端安装依赖”方式上传。索引可用且函数上传成功后，才上传小程序开发版并在微信公众平台设为体验版；开发、体验和生产环境必须隔离。

## 真实 CloudBase 与真机验收

至少使用两台不同屏幕尺寸的真机和两个不同测试微信身份；在弱网和正常网络各走一次。验收完成后清理测试账户数据。

1. 依次完成目标澄清、计划预览编辑、计划确认、Today 加载、开始任务、完成任务和难度反馈；刷新后确认状态仍一致。
2. 完成全部任务后生成并确认复盘，分别验证不确认和确认长期记忆两条路径，以及每日成长值上限。
3. 对待开始任务验证缩小与移到队尾；确认确定性操作在 AI 额度耗尽后仍可用。
4. 在用户点击事件中允许两种订阅消息；确认只创建本人当天的一条开始提醒和一条复盘提醒。可把测试提醒的 `sendAt` 临时调整为过去时间，等待最多五分钟，确认发送状态正确；完成后删除测试提醒。
5. 使用当日 `ai_quotas.count` 为 0 的专用测试账号，将 `runtime_settings/ai_quota.dailyAiQuota` 临时设为 2；调用任意有效 AI 工作流，前 2 次允许，第 3 次返回 `QUOTA_EXCEEDED`。把值改为 3 后，无需重启或重新部署，再调用 1 次应立即允许；这四个 AI 工作流按同一微信身份的 `openid` 与上海自然日共享计数。验收后恢复正式上限。无效输入不消耗次数，不得修改 `ai_quotas.count` 来制造通过结果。不要在验收记录中写入 OpenID 或生成正文。
6. 两个账号分别写入测试数据后，仅从第一个账号的“我的”页删除账户；确认第二个账号数据仍在，且 `deletion_audits` 只含安全审计字段。
7. 检查小屏、文字放大、底部安全区、加载与错误状态、触控目标和减少动态效果。若发现问题，先用最小自动化测试复现，再修复。

### 历史页双账号交接

1. 账号 A、账号 B 分别用匿名合成内容创建并确认历史计划；两边进入历史页，切换月份并选择脚印日期，确认各自只能看到本人的目标、任务状态与复盘，彼此不可见。
2. 删除前后都在本机临时验收表记录 A、B 在八个业务集合 `goals`、`plans`、`reviews`、`memories`、`reminders`、`ai_calls`、`ai_quotas`、`users` 的数量；只记录集合名和数量，不记录身份值或正文。
3. 仅删除账号 A：A 的历史页应清空，A 的八个业务集合计数均应变为 0；账号 B 的历史记录及八项计数必须与删除前一致。任一项不符即验收失败。
4. 检查新增 `deletion_audits` 文档只有 `_id`、`event`、`deletedAt` 等安全字段。截图、验收表和日志不得包含 OpenID、目标正文、任务正文、复盘正文、密钥或上游响应。
5. 在真机系统设置开启文字放大后重启微信体验版：确认月历日期仍可选择，目标、任务与复盘完整换行且不截断，滚动到最后一项时不被底部安全区遮挡。记录实际机型与字号；未执行不得标记为通过。

体验版提交前，须同时完成本页人工评测、两机真机验收和 Day 5 的提醒、额度、隔离删除复验；目前这些外部验收不由仓库自动测试替代。
